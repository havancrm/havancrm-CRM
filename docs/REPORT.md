## รายการที่ตรวจได้จริง (หลักฐาน = เทสต์ที่รันผ่าน)

**Data Mapping / ความถูกต้องของข้อมูล**
- อ่าน/เขียนตามชื่อ Header เท่านั้น: ทดสอบกับชีตที่สลับลำดับคอลัมน์ + มีคอลัมน์เสริม (`api.test`, `sheets.test`); Header ขาด = error ชัดเจนระบุแท็บ/คอลัมน์ ไม่เขียนผิดช่อง
- แถวสั้น (Google ตัดค่าว่างท้ายแถว) อ่านได้ทั้ง 18 แท็บ; รหัสลูกค้า/สินค้าคงเป็นข้อความ (`00123`, `8217*`)
- ไม่ซ้ำ/ไม่สูญหาย: บันทึกซ้ำด้วย `opId` เดิม = `duplicate`; ออฟไลน์แล้วออนไลน์ = 1 แถว; นำเข้าไฟล์เดิม (fileHash) ถูกปฏิเสธ; บิล/รายการซ้ำถูกข้าม; แก้คอลัมน์เฉพาะที่เปลี่ยน คอลัมน์อื่นไม่ถูกแตะ
- ยอดขาย = `SUM(bill_items.amount)` ตรงกับผลรวมดิบทุกช่วง; บิลที่มีรายการ VAT อยู่แล้วไม่บวกซ้ำ
- KPI หน้าแรก (ทั้งหมด/ปัจจุบัน/ห่างหาย/เลิกกิจการ) ตรงกับการคำนวณจากฐานและเปลี่ยนตามค่าที่ตั้งในตั้งค่า
- `activeFlag` ตามฐานจริง: **ว่าง = ดำเนินกิจการ, FALSE = เลิกกิจการ, TRUE = ดำเนินกิจการ**

**ทะเบียนสินค้า**
- คู่รหัสเก่า 5 คู่ที่ผู้ใช้ยืนยันถูกใช้เฉพาะเมื่อชื่อไม่ขัดแย้ง; ตัวอย่าง `9833*` ที่ชื่อขัดแย้ง **ไม่ถูกจับคู่**; รหัสไม่รู้จักไม่ถูกเดา; รหัสแยกโหล/ชุด/ลด 4 บาทไม่ถูกรวม
- ประวัติบิลแสดงชื่อ/จำนวน/ราคา/ยอดเดิม; รหัสไม่ตรงทะเบียนแสดงเฉพาะชื่อ + ป้าย "ไม่อยู่ในทะเบียนปัจจุบัน" (ไม่ตัดสินว่าผิด)
- สั่งซ้ำจากบิลเก่า: ข้ามรายการที่ไม่อยู่ในทะเบียน พร้อมแจ้ง ไม่เดารหัส
- หน้า "ตรวจรหัสที่ไม่ตรงทะเบียน": เลขบิล วันที่ ลูกค้า เสมียน บรรทัด + ส่งออก CSV

**หน้าจอ / UX** (ภาพใน `docs/screens/`)
- 21 เส้นทางเปิดได้ ไม่มี error, **ไม่เลื่อนแนวนอน**ที่ 390px, เมนูล่าง 5 ปุ่มตามลำดับ, ย้อนกลับถูกต้อง
- การ์ดลูกค้า 4 ช่องแถวเดียว, ป้ายกำกับ 2 คอลัมน์ (จำนวนตรง `customer_labels`), ทุกตัวเลขหลักกดเปิดรายชื่อได้, ทุกหน้ารายการมีช่องค้นหา
- Customer 360: 4 แท็บ, ปุ่มด่วน 5 ปุ่มแถวเดียวตามลำดับ (บันทึก | รูป+พิกัด | รับออเดอร์ | โทร | นำทาง), หน้าแรกมีบิลล่าสุด/สั่งประจำ/บันทึกก่อนเข้าร้าน/วันเกิด/รูปหน้าร้าน/สถานะพิกัด
- ฟอร์มเดียวสำหรับ เข้าพบ/โน้ต/นัดหมาย; GPS แนบได้ + ระยะจากพิกัดร้าน; รูปไม่บังคับ; อัปเดตพิกัดร้าน/รูปหน้าร้าน
- รอบลูกค้า (เลยรอบ/ใกล้ถึง/ขาดเข้าพบ) = ตรงกับที่คำนวณ; ปฏิทินรายเดือนแสดงจำนวนร้านต่อวัน กดวันแสดงรายชื่อด้านล่างหน้าเดียวกัน
- ออเดอร์: 4 แหล่งสินค้า, ตะกร้ารอดทั้ง Back และ reload, แก้จำนวน/ราคา, บันทึกร่าง/ยืนยัน (ไม่เกิดแถวซ้ำ), เอกสารไม่แสดงรหัสสินค้าแต่แสดงรหัสลูกค้า
- ตั้งค่า: รอบซื้อ/เกณฑ์ห่างหาย (บันทึกเป็นแถวใหม่ใน `systemSettings` คงค่า `comm`/`vatRate`), ป้ายกำกับ (admin), นำเข้า TTX, คุณภาพข้อมูล, ประวัตินำเข้า, ตรวจโครงสร้าง 18 แท็บ

**ระบบ / ความปลอดภัย / Cache**
- สิทธิ์: Google ID token → แท็บ `ACCESS` (`active`, `role`); ผู้ไม่มีสิทธิ์เห็นหน้าล็อกอิน; การตั้งค่า/นำเข้า/แก้ป้ายต้อง admin ทั้ง UI และเซิร์ฟเวอร์; `AUTH_MODE=dev` ถูกปฏิเสธเมื่อใช้กับชีตจริง
- CSP + `X-Frame-Options` + `nosniff`; ข้อความผู้ใช้ escape ทุกจุด
- เวอร์ชันเดียวกันใน app / `sw.js` / `?v=` / `/api/health` (ทดสอบอัตโนมัติ); service worker แคชตามเวอร์ชัน, API ไม่ถูกแคช; เปิดแอปออฟไลน์ได้
- ประสิทธิภาพที่ขนาดเท่าฐานจริง (1,383 ร้าน/~9 พันบิล/~23 พันรายการ): สร้างโมเดล ~20 ms, ค้นหา <10 ms

## บั๊กที่พบและแก้ระหว่างตรวจ (ไม่ใช่แค่ผ่านเทสต์)
1. `flush()` คิวซิงก์ไม่ส่งงานเลย (promise เก่าค้าง) — แก้แล้ว
2. ตัวจัดการคลิกซ้อนกันทุกครั้งที่เปลี่ยนหน้า (เปิด sheet ซ้ำ) — แก้ด้วย container ใหม่ทุกครั้ง
3. เรนเดอร์ซ้ำจากการซิงก์ล้างข้อความที่กำลังพิมพ์ — เช็กสถานะตอน timer ทำงาน + เลื่อนจนผู้ใช้เสร็จ
4. ตัวกรองชิปหน้าลูกค้าไม่อัปเดต; หมายเหตุ "ข้ามรายการ" หายเมื่อเรนเดอร์ซ้ำ; เริ่มแอปตอนออฟไลน์ไม่ได้ — แก้แล้ว
5. โควตา 50 subrequest/คำขอของ Cloudflare Free — จำกัด 4 คำสั่ง/คำขอ และอ่านแท็บ ACCESS ครั้งเดียว
