## ตามข้อที่สั่ง

**1. URL + SHA** — ดูท้ายข้อความตอบ (commit SHA ระบุหลัง push สำเร็จ). หมายเหตุ: repo จริงชื่อ `havancrm/havancrm-CRM` (ไม่ใช่ `havancrm/CRM`).

**2. เทียบกับ aCRM เดิม — ไม่ผ่าน (ยังเทียบโค้ด/หน้าจอไม่ได้)** `havancrm/A` ยังเข้าไม่ได้ (`add_repo` ถูกปฏิเสธซ้ำ) จึงสรุปไม่ได้ว่าฟังก์ชันครบ. สิ่งที่ทำได้คือ **เทียบรูปแบบแถวที่ aCRM เขียนไว้จริงในชีต** (visits/tasks/activities/orders/IMPORT_*) แล้วปรับให้ตรง:
 - สถานะออเดอร์ `รอส่ง/ส่งแล้ว` (+ `ร่าง`/`ยกเลิก` ของ CRM ใหม่), เลขออเดอร์ `NN+ddmmyy(พ.ศ.)` เช่น `01261169`, เชื่อมบิลด้วยหมายเหตุ `เชื่อมบิล N`
 - เข้าพบ = `visits.status=COMPLETED` + กิจกรรม `เข้าพบ`; **นัดหมาย = งาน `ติดตาม`** (ไม่ใช่ planned visit); โน้ต = กิจกรรม `โน้ต`; แตะโทร/นำทาง = กิจกรรม `โทร`/`นำทาง`; แก้ข้อมูลลูกค้า = `เปลี่ยนข้อมูลสำคัญ`
 - IMPORT_BATCHES (`TTX-BILL-yyyymmdd-nnn`, `TTX cp874`, `sha256:…`, `ok/ok_with_flags`), IMPORT_REVIEW (`pending/confirmed`, severity `low/medium`, รหัสปัญหา `PRODUCT_NOT_IN_REGISTER`)
 - ฟังก์ชันของ aCRM ที่เห็นร่องรอยในข้อมูลแต่ **ยังไม่ได้ทำ**: แก้/ลบโน้ต (`แก้บันทึก`, `ลบ`), ช่องเวลาในงานติดตาม, ข้อมูลรูปเพิ่ม (width/height/bytes), รหัสตรวจ `PRODUCT_NAME_NOT_EXACT_MATCH`/`PRODUCT_NO_DIRECT_BILL_CODE`. ต้องมีสิทธิ์ repo A หรือ zip ของ aCRM จึงจะเทียบครบ

**3. สร้างลูกค้าใหม่ — ผ่าน (E2E + unit)** ปุ่ม "เพิ่มร้านใหม่" (หน้าลูกค้า/ลูกค้าใหม่): รหัสชั่วคราว `N-yymmdd-XXXX` (อนุมานจาก opId จึงส่งซ้ำไม่เกิดร้านซ้ำ และต่างเครื่องไม่ชนกัน), เก็บชื่อ/เบอร์/ประเภท/ที่อยู่/ป้าย/พิกัด, ลงกิจกรรม `เพิ่มลูกค้า` + `changes`. **กันซ้ำ** ทั้งฝั่งแอป (เตือนทันที ต้องติ๊กยืนยันถ้าชื่อ/เบอร์ซ้ำ) และฝั่งเซิร์ฟเวอร์ (ปฏิเสธ `duplicate_customer` จากชื่อที่ normalise แล้วหรือเบอร์). **แยกจากร้านที่มีรหัสบัญชี**: ป้าย "ยังไม่มีรหัสบัญชี" ทุกที่, ตัวกรอง "ยังไม่มีรหัสบัญชี", ใบส่งสินค้าพิมพ์ "รอรหัสบัญชี". ผู้ดูแลกด "ผูกรหัสบัญชี" → เปลี่ยนรหัสพร้อมกันในทุกแท็บที่อ้างลูกค้า (ตรวจแล้ว: customers, phones, labels, bills, orders, visits, tasks, activities, gps, photos), ปฏิเสธรหัสที่มีอยู่แล้ว. นำเข้ารายงานลูกค้า TTX จะจับคู่ร้านชั่วคราวที่ชื่อ/เบอร์ตรงแล้วผูกรหัสแทนการเพิ่มซ้ำ

**4. ลูกค้าใหม่ในรายงาน — ผ่าน** สองกลุ่มแยกกัน: **ซื้อครั้งแรก** (จากบิล) และ **เพิ่มทะเบียน** (จากกิจกรรม `เพิ่มลูกค้า`, ยังไม่ซื้อก็แสดง) ร้านชั่วคราวไม่ปรากฏใน "ซื้อครั้งแรก" (E2E ตรวจ)

**5. เกณฑ์รอบซื้อ/ห่างหาย/ขาดเข้าพบ — ผ่านบางส่วน**
 - **แก้ให้ตรง aCRM จริงแล้ว (อ่านจากซอร์ส v77)**: ห่างหาย = ไม่ซื้อเกิน `dormDays 365` วันหรือยังไม่เคยซื้อ; รอบลูกค้า = บิลล่าสุด + `visitDef 30` วัน (ไม่มีรอบถ้าไม่เคยติดต่อ หรือเงียบเกิน 365 วัน); เกินรอบนาน > `lateDays 90`; ใกล้ถึงรอบ ≤ `nearDays 7`. ไม่มีสูตรรอบจากประวัติ (ที่ผมเคยตั้งเองถูกถอดออกแล้ว)
 - ตั้งเองมีค่าเดียว: `newDays 90` (ลูกค้าใหม่) ยังไม่ยืนยัน
 - ผลบนข้อมูลจริง (ตรวจด้วยสคริปต์): ทั้งหมด 1,383 · ปัจจุบัน 895 · ห่างหาย 314 · เลิกกิจการ 174 ; จำนวนรอบรายเดือนใกล้เคียงภาพ ART ที่ผู้ใช้ส่งมา

**6. นำเข้า TTX จากไฟล์จริง — ผ่านในระดับตรรกะ (ยังไม่ได้เขียนลงชีตจริง)** ไฟล์จริงเป็นรายงานพิมพ์ cp874 ไม่ใช่ตารางมีหัวคอลัมน์ ตัวอ่านเดิม (เดา) **ใช้ไม่ได้ จึงเขียนใหม่**. ผลกับไฟล์จริง:
 - บิล: อ่านได้ **9,904 บิล / 31,164 รายการ**, ยอดรวมตรง footer 12,515,075.01 ; เทียบกับฐาน: **ตรงกัน 9,899, ต่างยอด 3, ใหม่ 1 (บิล 386627 ลูกค้า 000), flag 141**; แถวอ่านไม่ได้ 3 (รายการสินค้าตัวอย่างยอด 0 ที่ quote ในไฟล์เสียจริง รายงานเป็นรายการตรวจ ไม่เดา)
 - กติกาแปลงที่เทียบกับบิลจริง 9,900 ใบ: บรรทัด `0015 ภาษีมูลค่าเพิ่ม` ไม่เก็บเป็นรายการ + `vatMode=VAT_OUT`; มีรายการ `0014 ขอใบกำกับภาษี` = `VAT_IN`; ยอดหัวบิลต่างรายการ → ใช้ผลรวมรายการ + flag `HEADER_NE_ITEMS`; "เงื่อนไข/พนักงาน" แยกเป็น paymentTerm/openedBy (ตรงฐาน ~99.6%). ยอดขายจึงไม่บวก VAT ซ้ำ
 - ลูกค้า: 1,382 ราย **มีในฐานครบ ไม่มีรายใหม่** (ไม่แก้ของเดิม)
 - จำลองนำเข้าจริงในหน่วยความจำ: ตัดบิลตั้งแต่ 2026-11-01 (261 บิล ยอด 280,445) ออกจากสำเนา → นำเข้าไฟล์จริง → ได้ยอด 280,543 กลับมา (ต่าง 0.03% จากรหัส/ยอดที่ aCRM แก้ในฐาน); ไม่มีเลขบิล/บรรทัดซ้ำ; นำเข้าไฟล์เดิมซ้ำถูกปฏิเสธ; ส่งชุดเดิมซ้ำไม่เพิ่มแถว
 - เชื่อมออเดอร์กับบิลตามแบบ aCRM (`เชื่อมบิล N`): ลูกค้าเดียวกัน + ยอดเท่ากัน + วันที่บิลไม่เกิน 7 วันหลังออเดอร์ + จับคู่ได้ชัดเจนเพียงรายการเดียว (กติกานี้ผมอนุมานจากข้อมูล 40 ออเดอร์)

**7. ใบส่งสินค้าชั่วคราว — ผ่านตามต้นแบบ** วาดบนแบบฟอร์ม Havan เดิม (`template.png`) ด้วยตำแหน่งฟิลด์จากตัวอย่าง `index.html`; ทดสอบกับออเดอร์จริง `01121169` ได้ข้อความทุกฟิลด์ตรงตัวอย่าง (ชื่อร้าน รหัส ชื่อสินค้า `50 แกลลอน`, 125.00, 6,250.00, 10,600.00, `(หนึ่งหมื่นหกร้อยบาทถ้วน)`). หน่วยนับมาจากไฟล์ราคา (ครบ 366 รหัส ชื่อตรงทะเบียน 100%) — **แนบเฉพาะหน่วย ไม่แนบราคา** เพราะไฟล์สถิตบน Worker เปิดสาธารณะ. หลายหน้าเมื่อเกิน 15 รายการ, พิมพ์/PDF, คัดลอก, แชร์.
 - **ตัดสินใจแล้ว (เจ้าของ 27 พ.ย.)**: คงช่อง **รหัสสินค้า** ตามต้นแบบ พิมพ์รหัสเป็นค่าเริ่มต้น (ปิดได้ในหน้าเอกสาร). เลขที่ในตัวอย่างเป็น `TN69/405405` (เลขของระบบบัญชี) แต่ CRM ใช้เลขออเดอร์ของตัวเอง
